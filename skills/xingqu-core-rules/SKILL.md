# 星曲自動化：共用規則

執行任何 `xingqu-mode-*` 子技能前，這份規則必須已經在上下文中（由 `xingqu-auto-play` 主流程先載入一次）。

遊戲基本資訊：7road 的 Wartune Ultra（中文名「星曲」），伺服器 Cloud City，帳號 <你的帳號>，網址 7.wan.com/game/play。使用 mcp__claude-in-chrome 工具操作，座標以 1214x667 的截圖座標為準。

## 通用規則（每個模式都要遵守）

1. **先截圖再點擊，一次一動作**：每進入一個新畫面，第一個動作是截圖確認，再點擊；每次點擊後都要截圖確認結果。換畫面的導覽不要盲點串接。
2. 同畫面內的固定流程可用 browser_batch 串接，**但每個 batch 最多只放一個會改變狀態的點擊**；換畫面、結果不確定的操作要逐步截圖。
3. **絕對不點**：「購買挑戰次數」、英靈競技右下角「＋」、任何要消耗鑽石／道具／金幣才能執行的按鈕或確認視窗（包括祕境「使用秘境鑰匙」確認、內政廳「額外徵收 💎10」）。誤開立刻取消並回報。
   - 例外（免費額度内的必經確認視窗，允許點擊）：祕境掃蕩前「是否消耗1次今日進入次數」；地下迷宮「使用迷宮鑰匙獲得雙倍收益」勾選框（使用者已自備鑰匙庫存，明確同意固定每次都勾選，這是「不主動花費資源」原則唯一例外）；紫晶礦場「領取提示」的免費普通礦車確認。
4. **不主動領取獎勵**，除非使用者明確要求。但下列視為機制自動發放，可以直接收：累勝獎勵彈窗、祕境⾜觀星⾜地下迷宮⾜紫晶礦場⾜徵收的產出、外城打怪擊殺後的系統訊息獎勵。
5. 只做技能文件裡列出的功能，其他一律先問使用者。包括：多人競技場、競技商店、排行榜、祕境列表裡古代城堡以外的關卡、多人祕境、深淵／煉獄迷宮、迷宮商店、高級礦車、內政廳「升級」都不在範圍內。
6. 如實回報，輸了就寫輸，不美化。
7. 每個模式開始前先讀「剩餘次數」。若已是 0，該模式不打，回報「次數為 0，未執行」，繼續下一個。
8. **累勝獎勵彈窗**（單人競技累計獲勝 10/20/35/50 次時出現）：只有「領取」一個按鈕，點外側或 Esc 關不掉。直接點「領取」關掉後繼續，不算違反不主動領獎規則，回報中需註明。
9. **掉線／登入頁處理**：畫面跳到登入頁、公告頁或斷線提示，立刻停止，不自己按「進入遊戲」（預設伺服器可能不是 Cloud City）。同理，若地圖整片變暗、看不到角色與怪物且等待後仍未恢復，也不要自己重新整理網頁，停下回報。
10. **遊戲彈窗**：副本邀請、組隊邀請、活動公告等非流程內的視窗，一律不接受、用關閉或取消鈕關掉，并在回報中註記。純資訊性系統橫幅不用特別處理。**場景內的金色活動圖示**（例如人物附近的「累充排行」「領主召回」）也是可點擊的活動入口，點場景物件前要避開這些圖示，誤開依本條關閉即可。
11. **主城座標警告**：入口頁關閉鈕 (1132,74) 只適用於「競技場入口頁」。在主城畫面，同一個位置是地圖切換區塊，點了會切地圖。**地圖切換區塊**（右上角，約 1094,107 與 1094,150 上下兩格）只會列出「另外兩張地圖」，同一個位置在不同地圖代表不同目的地：天空之城時上格「外城」下格「內城」；內城時上格「天空之城」下格「外城」；外城時上格「內城」下格「天空之城」。**一律看文字標籤再點，不要硬記座標**。
12. **人物所在地圖確認**：畫面右上角、金幣數字右側顯示目前地圖名稱（約 1105,50 附近）。開始任何模式前，依該模式的前置條件確認地圖正確：祕境⾜地下迷宮⾜紫晶礦場要天空之城，徵收要內城，觀星⾜外城打怪要外城。紫晶礦場進入後會被傳送到專屬場景，必須點「返回」才能回到天空之城（見 xingqu-mode-mine）。
13. **子技能呼叫規範**：呼叫任一 `xingqu-mode-*` 子技能時，使用 Skill 工具，`skill` 參數要用當下技能清單裡顯示的完整名稱（含外掛前綴）。**呼叫失敗或在清單中找不到對應技能，必須立即停止並回報使用者，嚴禁憑記憶或猜測硬跑該模式的流程。**
14. **排程注意**：若使用者要求排程重複執行，一律使用 `send_later`（綁定本工作階段，保有瀏覽器工具），**不可使用** `create_trigger`（會開啟沒有 Claude in Chrome 的全新工作階段，導致排程執行時無法操作瀏覽器）。
15. **連線健康檢查（開工前必做）**：不管是使用者即時對話觸發、還是排程（send_later）觸發，在呼叫任何 `xingqu-mode-*` 子技能、開始實際操作之前，先做一次連線測試：`tabs_context_mcp` 取得分頁後，對該分頁嘗試一次 `screenshot`。
    - 若截圖成功，正常繼續往下執行。
    - 若失敗且錯誤訊息是分頁／工作階段連線類的問題（例如「不在工作階段的分頁群組中」「Tool ... failed in the extension」之類），**不要反覆開新分頁或無限重試**：最多再重試 2 次（可嘗試 `tabs_context_mcp createIfEmpty:true` 重新握手），若仍然失敗，立即停止整個流程，不執行任何模式，回報「連線異常，未執行任何項目，需重新連接 Claude in Chrome 後再試」，並簡短說明已嘗試過的排查步驟。
    - 本條規則的目的是避免在斷線狀態下浪費大量操作與用量卻毫無進展，讓使用者能第一時間知道要處理連線問題。

## 對手選擇規則（單人競技、英靈競技共通；其他模式不適用）

1. 只考慮「戰力低於我」的對手。
2. 在符合的對手中，挑「積分最高」的。
3. 挑戰前若有確認視窗，先看「勝利／失敗」積分變化再按挑戰。
4. 沒有符合的對手時，用該模式的「換名單」方式更新，直到有可打的對手；換名單有次數上限時，用完就打現有名單裡最接近條件的，避免無限迴圈。

## 回報格式共同規範

各模式執行完後，回傳給主流程的資料包含：1) 開始→結束狀態與剩餘次數；2) 逐場／逐次明細；3) 異常與失誤（沒有就寫「無」）。整合成完整回報由 `xingqu-auto-play` 主流程負責。
