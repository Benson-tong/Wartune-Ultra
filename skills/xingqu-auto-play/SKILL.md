# 星曲：Wartune Ultra 遊玩自動化（主流程）

觸發詞：使用者說「星曲」（或「跑星曲」「星曲日常」），或直接指名某個項目（例如「星曲 只跑紫晶礦場」「幫我打一下英靈競技」「星曲：徵收和觀星就好」）。遊戲是 7road 的 Wartune Ultra（伺服器 Cloud City，網頁版，中文名「星曲」），帳號 <你的帳號>。

**本 skill 是主流程／派工者**：所有畫面座標、點擊步驟、資源消耗規則、對手選擇規則等實際操作細節，都寫在下面對照表列出的各個子技能檔案裡，本檔案本身不包含任何座標或畫面操作說明。本檔案只負責：(1) 載入共用規則、(2) 判斷本次要跑哪些項目、(3) 依序呼叫對應的子技能、(4) 呼叫失敗時的處理、(5) 彙整最終回報。

使用者用「星曲」觸發，就是已授權整套流程，不必逐步詢問；指定單一/多個項目時，也視為已授權該項目，同樣不用再問。遇到本文與各子技能都沒寫的情況才停下來問使用者。

## 第一步：載入共用規則

開始任何項目之前，先用 Skill 工具呼叫 **xingqu-core-rules**（技能清單上可能帶外掛前綴，例如 `anthropic-skills:xingqu-core-rules`，呼叫時要填清單上當下顯示的完整名稱），取得：通用安全規則（截圖後點擊、絕對不點清單、地圖切換與確認方式等）、對手選擇規則（單人競技／英靈競技共用）、回報格式共用規範。這一步是所有項目共通的前置作業，只做一次。

若這一步呼叫失敗（技能不存在或呼叫報錯），**立即停止整個流程**，回報「共用規則載入失敗，未執行任何項目」與錯誤內容，不要憑記憶裡的舊規則繼續執行。

## 第二步：判斷本次執行範圍

1. 使用者只說「星曲」「跑星曲」「星曲日常」等，未指名任何項目 → 執行下方「預設完整順序」的全部 8 個項目（已包含守衛遠征與外城打怪）。
2. 使用者明確指名一個或多個項目（不論用遊戲內名稱「單人競技」「英靈競技」「祕境」「地下迷宮」「紫晶礦場」「守衛遠征」「徵收」「觀星」「外城打怪」，或口語說法如「礦場」「星星」「內政廳」等能明確對應到下表某一項的說法）→ **只執行使用者指名的項目**，依「預設完整順序」裡的相對先後順序排列執行，跑完指名的項目就回報，不補跑其他未指名的項目。
3. 若使用者指名的文字無法對應到下表任何一個項目，停下來回報「無法辨識項目：<文字>」，並列出目前支援的項目清單讓使用者確認，不要自行猜測執行其他項目。

單人競技與英靈競技已合併為同一個子技能 xingqu-mode-arena，呼叫一次即依序完成兩者。

守衛遠征（第 5 項）為新加入項目，詳細操作與資源消耗規則見 xingqu-mode-guard；該技能部分座標、以及「一鍵掃蕩」在剩餘次數>0時點擊後的實際畫面，尚待首次正式執行時截圖驗證與校正。若執行中發現畫面與文件明顯不符，依 xingqu-core-rules 第13條精神停止該項目並回報實際狀況，不要憑猜測硬跑，不影響其他項目繼續執行。

外城打怪（第 8 項）已從實驗功能正式納入預設順序，接在觀星之後执行：只打「普通」與「精英」且等級 160 的怪物，BOSS 一律不主動攻擊；戰鬥中的截圖／確認頻率可拉長到約 1 分鐘一次以節省用量，該模式結束後其餘模式（若還有排定）恢復正常頻率（詳細規則見 xingqu-mode-outer）。每日擊殺配額依左側面板當下數字為準，配額為 0 時同樣比照其他模式回報「次數為 0，未執行」並跳過。

## 子技能呼叫規則

1. 呼叫前，先確認 Skill 工具目前的技能清單裡，該子技能的**完整顯示名稱**（可能帶外掛前綴，例如 `anthropic-skills:xingqu-mode-mine`），一律用清單上當下顯示的完整名稱呼叫，不要憑記憶用舊名稱或猜測前綴。
2. **若呼叫失敗、找不到、或工具回報任何錯誤**：立即停止該項目，不猜測、不憑記憶用自己原本知道的舊流程繼續操作，直接在回報中列出「項目：<名稱>，狀態：呼叫失敗，錯誤：<訊息摘要>」，並繼續判斷是否要跳到下一個排定的項目（單一項目呼叫失敗不影響其他已成功、尚未執行的項目）。
3. 已成功呼叫並執行完的項目不受後續項目失敗影響，各自的結果都要如實列入最終回報。
4. 每個子技能執行完後，會回傳／留下該項目的執行結果（開始/結束次數或積分、逐場明細、異常事項等），主流程要收集這些結果，供第三步彙整回報使用，不要重新臆測或美化子技能已回報的結果。

## 第三步：彙整回報

所有排定項目跑完（或因失敗/次數為0跳過）後，依 xingqu-core-rules 裡的回報格式共用規範，將本次執行的所有項目彙整成一份完整回報，至少包含：

1. 本次執行範圍（預設完整順序，或使用者指定的項目清單）。
2. 逐項目結果：每個項目的開始→結束數值（積分/次數/資源）、逐場或逐次明細、是否因次數為0跳過、是否呼叫失敗。
3. 異常與失誤彙整：各項目回報的誤點、彈窗、資源消耗異常等，集中列在同一份回報裡，不要分散或遺漏。
4. 結尾附「尚未回答的問題」清單（若有），已定案事項只留一行結論。

用表格與編號清單呈現，不要大段散文。

## 擴充功能（後續追加）

使用者會陸續追加新項目。追加規則：

1. 新項目先以獨立子技能的形式建立（用 propose_skills 的 kind: new），內容包含入口、操作細節、資源消耗規則、回報格式，不寫進本主流程檔案。
2. 新項目穩定可信賴後，才在本檔案「預設完整順序與子技能對應表」補上一行，並視使用者要求決定插入順序；尚在驗證/實驗階段的新項目，維持「需另外明確觸發」，不排入預設完整順序，直到使用者確認要加入為止。
3. 未列在對照表、且使用者也沒有在當次明確指名的項目，一律不執行。
